## Acceptance criteria
- [ ] AC-01 — A first-run user can authorize GitHub and see accessible personal and organization repositories; permission and installation gaps are explained with a recovery path. Evidence: pending
- [ ] AC-02 — The repository list is paginated and does not claim to show a repository that GitHub has not exposed to the authorized app. Evidence: pending
- [ ] AC-03 — The user can choose a parent folder and clone a selected repository under its repository name. Existing/non-empty target paths are protected from overwrite. Evidence: Clone, existing-checkout detection, and Add Folder validation implemented; matching-remote and no-overwrite unit tests passed; authenticated clone smoke remains pending.
- [ ] AC-04 — The project view distinguishes GitHub remote branches/commits from local branches, working-tree state, and linked worktrees. Evidence: pending
- [ ] AC-05 — The branch graph can navigate to the related commit and, where available, PR/merge record. Deleted remote branches remain visible as historical PR/merge records when GitHub still exposes that data. Evidence: Interactive GitHub branch lanes load up to 100 commits for the selected branch; selected commits show their full message and GitHub link. Parent/merge topology and deleted-branch PR history remain pending.
- [ ] AC-06 — PR detail includes the fields listed in scope, changed-file patches when GitHub provides them, review history, inline review comments, and conversation comments, with links to the authoritative GitHub page. Open PRs expose comment, review, and confirmed merge actions; closed PRs remain inspectable without write actions. The contribution graph keeps GitHub's contribution-calendar counts; comments and merges remain activity rather than invented contribution types. Evidence: Open/closed PR summaries, PR descriptions, changed-file patches, inline review comments, conversation comments, review history, comment/review submission, and confirmed merge are implemented; backend endpoint coverage passed. Reviewer requests, labels, checks, and live GitHub permission/action validation remain pending.
- [ ] AC-07 — Issues, contributor identities, and recent items show loading, empty, stale, and access-error states distinctly. Evidence: pending
- [ ] AC-08 — Preview links require a user click and open only recognized web URLs in the system browser. Evidence: pending
- [ ] AC-09 — New/changed PR detection covers all accessible repositories by default, runs on foreground and the configured polling schedule while the app is running, and shows per-repository stale state and rate-limit delays. Full PR details load on demand. Evidence: pending
- [ ] AC-10 — GitHub writes are limited to explicit PR comments, reviews, and confirmed merges. Clone/fetch remain read operations; local cloning writes only under the user-selected destination. Evidence: PR write APIs are limited to issue comments on PRs, PR reviews, and PR merge; backend test verifies those methods and the merge request. Manual GitHub App Pull requests: write setup and live action smoke remain pending.
- [ ] AC-11 — Any enabled AI explanation identifies its source records. AI is unavailable until its provider/data-handling choice and consent flow are defined. Evidence: pending
- [x] AC-12 — The navigation consistently presents repositories as projects, with distinct cross-project **All Projects** and **Activity** destinations and project-specific **Overview**, **Branches**, **Commits**, **Pull Requests**, and **Issues** destinations. Evidence: `WorkspaceFlowTests.testSidebarOpensActivityAndSettings` passed with the compact year selector and 2025 selection; 2026-10-30.
- [ ] AC-13 — The interface targets the latest macOS release supported at implementation and remains usable with keyboard navigation, VoiceOver labels, and system appearance settings. Evidence: pending
- [ ] AC-14 — Repository cards adapt their column count and content width to the available window size, including fullscreen; commit messages and PR descriptions appear with their own records and can be expanded or minimized, messages offer readable Preview and raw Markdown modes, timestamps use `MMM d, yyyy, h:mm a`, project navigation buttons have consistent padding, and the sidebar identifies the signed-in GitHub username. Evidence: Adaptive repository and project navigation grids, padded navigation controls, inline commit details, per-commit and per-PR Expand/Minimize plus Preview/Markdown controls, block-aware Markdown renderer, formatted GitHub timestamps, and GraphQL viewer identity implemented; all 14 backend tests passed, including Markdown block conversion. Signed-in PR #2 visually confirmed with separate headings, paragraphs, lists, Markdown source toggle, and minimize/expand behavior. Overview heading, description, and summary visibly centered in the fullscreen-sized app; focused Activity/sidebar UI flow passed. Narrow-window and commit-message visual review remain pending.
